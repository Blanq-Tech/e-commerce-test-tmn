# Лог подхода

Здесь честно: что пробовал, что не взлетело и почему, что в итоге сделал.
Это важнее «красивого» кода — антибот Ozon заставил перебрать несколько стратегий.

## Хронология

### Подход 1. «Голый» HTTP к мобильному API (по перехвату из Burp)

Из мобильного приложения через Burp снял запрос:
`GET api.ozon.ru/composer-api.bx/page/json/v2?url=/search/?text=...` со всеми
заголовками и куками (`__Secure-access-token`, `abt_data`, `x-o3-fp` и т.д.).

- **Прямой запрос с Mac → таймаут.** DNS/TLS до `api.ozon.ru` не резолвится/не
  устанавливается — IP вне РФ заблокирован геолокацией.
- **Нашёл, что трафик телефона идёт через Burp** (`127.0.0.1:8080`, Java-процесс).
  `X-Ad-Params` из запроса в base64 расшифровывается как
  `pHost=192.168.0.214&pPort=8080...` — телефон реально проксируется на этот Mac.
- Пошёл через Burp как апстрим — **транспорт заработал** (nginx ответил).

### Подход 2. Бой с антиботом на уровне HTTP

- Сервер на каждый запрос отдавал **307 с ротацией `__Secure-ETC`** и счётчиком
  `&__rr=N`. `curl -L` зацикливался: статичный `Cookie:` не обновлял ETC.
  Решил cookie-jar'ом (requests.Session / ручное обновление ETC) — гейт прошёл.
- Дальше — **403 «fab» (fingerprint anti-bot)**: `{"incidentId","blockURL",
  "timeoutSec"}`. Перебрал:
  - полный набор заголовков один-в-один с перехватом → 403;
  - заметил, что часть «заголовков» (`MOBILE_APP_TYPE`, `x-o3-app-version`) на самом
    деле **куки**, а не заголовки; убрал лишнее → всё равно 403;
  - байт-в-байт реплей сырыми сокетами через Burp (точный порядок заголовков,
    `Accept-Encoding: gzip, deflate, br`, без лишнего `Connection`) → 403;
  - cooldown 35с, без спешки → 403.
- **Ключевая диагностика:** прогнал разные эндпоинты одной и той же сессией:
  - `/` (главная) → **200** ✅
  - `/id/orders` → **200** ✅
  - `/search/`, `/product/`, `/cart` → **403 fab** ❌

  Вывод: **сессия живая**, но «чувствительные» эндпоинты (поиск/карточка) защищены
  строже и валидируют **свежий, одноразовый `x-o3-fp`**, который генерит нативный
  антифрод-SDK приложения. Реплей статичного `x-o3-fp` для них не проходит.
- Проверил гипотезы «прогрев + ротация `abt_data`» и «тот же keep-alive коннект» —
  `abt_data` на успешных ответах **не ротируется**, прогрев не снимает блок поиска.

**Итог подхода:** воспроизвести подпись поиска «голым» HTTP без реверса
нативного SDK Ozon — нереалистично в рамках задачи.

### Подход 3 (рабочий). Реальный браузер + пул прокси

Раз антибот ловит фингерпринт — берём **настоящий Chromium (Playwright)**: у него
честный TLS/JS-фингерпринт, он сам проходит челленджи. Плюс гоним трафик через
**пул резидентных RU-прокси** (геоблок + ротация IP против банов).

Что сделал:
- `playwright async` + изолированный контекст на воркера (свои куки/UA/viewport);
- лёгкий stealth (`navigator.webdriver`, `languages`, `plugins`, `window.chrome`);
- разбор выдачи: собираю `href` товарных плиток в порядке DOM → SKU → позиция;
- пагинация по `&page=N` до глубины 100;
- **пул прокси с ротацией и cooldown** (`proxy.py`): `host:port:user:pass`,
  round-robin, бан «спалившегося» IP на 90с, авто-смена прокси при 403/таймауте;
- **оркестрация**: семафор-пул из N асинхронных воркеров поверх одного браузера,
  ретраи с экспоненциальным бэкоффом;
- чистую логику разбора и пул вынес в отдельные модули и **покрыл тестами**
  (12 тестов, без браузера — быстро и детерминированно).

## Что отдавал ИИ и что из этого взял

- *«Разбери, почему Ozon отвечает 307 с `__rr` и как пройти гейт»* — подсказал
  про cookie-jar и обновление `__Secure-ETC`; взял идею, реализовал руками.
- *«Сравни поведение эндпоинтов под одной сессией»* — оформил диагностический
  прогон (главная vs поиск), который и показал, что блок именно на поиске.
- *«Сделай пул прокси с ротацией и cooldown, потокобезопасный»* — каркас класса
  `ProxyPool` сгенерил, дальше правил под Playwright (формат `to_playwright`,
  бан по `monotonic`, выбор наименее «протухшего» при полном бане).
- *«Оркестрация N воркеров на одном браузере, async»* — взял схему semaphore +
  `asyncio.gather`, контекст-на-задачу добавил сам ради изоляции.

## Что пришлось менять руками

- Убрал из заголовков то, что на деле было куками (ложный след от ИИ-генерации).
- Переписал слияние SKU между страницами: вместо round-trip «SKU→псевдо-href→SKU»
  сделал упорядоченный аккумулятор с `set` для дедупа.
- Прокси задаю **на уровне контекста**, а не браузера — иначе не было бы ротации
  между воркерами (ИИ по умолчанию ставил proxy в `launch`).
- Добавил детект страницы-заглушки антибота по маркерам и перевод задачи на ретрай
  с новым IP.

## Честный статус

- Логика, оркестрация, ротация прокси, ретраи, Docker, тесты — **готовы и
  протестированы**.
- Стабильность сбора живой выдачи Ozon упирается в **качество прокси**: на
  датацентровых IP антибот выгорает быстро, нужны резидентные. Это отражено в
  `architecture.md` (раздел про прокси и бюджет).
